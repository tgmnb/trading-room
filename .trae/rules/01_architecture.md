# 项目架构规范

## 1.1 总体架构

采用「太子 + 三省六部 + 早朝官 + 御史台 + 专项机构」架构：

```
用户 
  ↓
太子（分拣与立项）
  ↓
中书省（规划与拆解）
  ↓
门下省（审议、封驳、返工）
  ↓
尚书省（派发、状态流转、汇总回奏）
  ↓
六部 / 专项机构（执行）
  ↓
尚书省（汇总回奏）
  ↓
早朝官（日度/周度/重大复盘会议）
  ↓
御史台（独立监察）
```

## 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| 人机关系 | 用户是最终决策者，系统负责辅助研究、制度约束、风险提醒、执行监督、问责复盘 |
| 反幻觉 | 不知道就说不知道，不确定说明来源，关键结论带证据等级(A/B/C)，区分事实/推断/假设 |
| 分权 | 研究归研究、审核归审核、风控归风控、执行监督归执行监督、复盘归复盘 |
| 结构化 | 所有输出必须进入模板化结构，不允许自由散文式分析直接进入决策层 |
| 成长优先 | 系统不仅要提高当下研究质量，还要围绕用户的稳定性弱点进行训练 |

## 1.3 系统分层

### 1.3.1 治理层

治理层负责分拣、规划、审议、派发、汇总与节律管理，不直接承担主要业务研究执行。

| 组成 | 职责 | 品级 |
|------|------|------|
| 太子 | 任务分拣与立项 | 储君 |
| 中书省 | 规划与拆解 | 正一品 |
| 门下省 | 审议、封驳、返工 | 正一品 |
| 尚书省 | 派发、状态流转、回奏汇总 | 正一品 |
| 早朝官 | 日度、周度、重大事项会议节律 | 正三品 |

### 1.3.2 独立监察层

独立于治理层和业务层，直接向用户负责。品级高于六部。

| 组成 | 职责 | 品级 |
|------|------|------|
| 御史台 | 独立监督用户本人和系统整体质量，专查计划外行为、重复错误与机会遗弃 | 从一品 |

### 1.3.3 业务层

业务层负责投资相关的专业执行。

| 组成 | 职责 | 品级 |
|------|------|------|
| 吏部 | 行为画像、成长训练、制度提醒 | 正二品 |
| 户部 | 仓位、组合、相关性、止损、账本 | 正二品 |
| 礼部 | 盘前、盘中、盘后流程，定时任务，配额治理，文书整编，简报与纪要 | 正二品 |
| 兵部 | 投资研究、预期差研判、机会排序、交易计划 | 正二品 |
| 刑部 | 执行监督、违规稽核、偏差归因、纪律问责 | 正二品 |
| 工部 | 数据、回测、技术统计、监控、自动化 | 正二品 |

### 1.3.4 专项机构层

用于承接六部难以优雅容纳、但长期有价值的职能。

| 组成 | 职责 | 品级 |
|------|------|------|
| 皇城司 | 资讯中台、新闻与用户临时想法整理、议题入池 | 正三品 |
| 发改委 | 长期逻辑、行业景气、基本面跟踪、主题/行业榜单 | 正三品 |
| 国策库 | 延迟汇报、长期跟踪、报告嵌入的议题池（共享机制） | 正三品 |

## 1.4 组织原则

- 三省是治理骨架，六部是执行肌肉
- 三省不替代六部执行，六部不越权代替三省治理
- 门下省为必经节点，没有放行不得进入执行层
- 尚书省是状态机与派发中枢，不是普通行政秘书
- 早朝官不是装饰角色，而是维持制度节律的会议节点
- 专项机构用于承接高频情报汇流、长期产业跟踪、延迟汇报议题等“六部不够优雅”但确有必要的功能
- 门下省负责审议与加闸，不负责做部门间逐站消息中继；真正的流转编排权仍应留在尚书省

## 1.6 模块划分标准

| 模块 | 职责 | 边界 |
|------|------|------|
| agents/ | 各部门 Agent 的 SOUL.md 定义 | 每个部门一个目录，SOUL.md 包含该部门所有 Agent |
| dashboard/ | 用户界面展示 | 仅负责展示，不执行业务逻辑 |
| scripts/ | 数据同步、运维工具 | 后台任务，不直接面向用户 |
| tests/ | 单元测试、集成测试 | 覆盖核心功能模块 |

## 附录：证据等级定义

| 等级 | 定义 | 示例 |
|------|------|------|
| A 级 | 原始数据、公告、行情事实 | 财报数据、公告文件、行情数据 |
| B 级 | 统计研究、历史回测、高质量二手资料 | 回测报告、券商研报 |

## 附录：审查结论类型

| 结论 | 说明 | 后续动作 |
|------|------|----------|
| 同意 | 允许进入尚书省流转 | 派发执行 |
| 封驳 | 退回中书省重做 | 修订后重新提交 |
| 缓议 | 逻辑有道理，但时机/证据/替代成本不足 | 进入观察池或待补材料 |

## 附录：关键制度铁律

| 铁律 | 内容 |
|------|------|
| 太子只做分拣，不做研究 | 太子负责分拣立项，不得直接规划任务细节、下研究结论、发往六部执行 |
| 中书省只做规划，不做主要业务执行 | 中书省负责规划拆解，不得直接承担主要技术研究、基本面研究、回测、风控核算 |
| 门下省为必经审议层 | 任何正式任务要进入六部执行，必须经过门下省审议 |
| 尚书省掌控状态机与派发权 | 尚书省负责状态维护与派发，不得私自修改门下省审议结论、直接代替六部做专业判断 |
| 六部只在授权范围内执行 | 六部负责各自专项工作，不得越权替代其他部门或三省 |
| 早朝官维持节律 | 早朝官负责盘前/盘后/周度会议，防止任务碎片化 |
| 礼部掌控定时节奏与配额纪律 | 礼部负责定时任务编排与配额治理，不得擅自删改已批准的重要任务 |
| 御史台独立监督，不受盈利结果免责 | 即使最终盈利，只要存在计划外违规，也可被御史台和刑部记录为纪律问题 |

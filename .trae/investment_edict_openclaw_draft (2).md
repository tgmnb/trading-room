# 投资版 Edict / OpenClaw 三省六部草案 v0.1

## 1. 目标定义

本系统不是自动替代用户进行交易决策，而是作为“投资研究、交易计划、执行监督、复盘训练”的制度化辅助系统。

系统的首要目标不是提高建议数量，而是提高：

1. 决策质量的一致性
2. 机会横向比较能力
3. 计划执行纪律
4. 复盘归因质量
5. 用户在交易中的长期成长

系统的第二目标才是提高研究效率、信息跟踪效率和统计验证效率。

---

## 2. 核心设计原则

### 2.1 人机关系原则

- 用户是最终决策者。
- 系统负责辅助研究、制度约束、风险提醒、执行监督、问责复盘。
- 系统可以强硬指出问题，但不能越权代替用户承担最终主观判断。

### 2.2 反幻觉原则

任何 agent 不允许“像是知道”地胡乱作答。

统一要求：

- 不知道就必须明确说不知道。
- 不确定就必须说明不确定来源。
- 判断必须区分事实、推断、假设。
- 关键结论必须给出证据等级。

### 2.3 分权原则

- 研究归研究。
- 审核归审核。
- 风控归风控。
- 执行监督归执行监督。
- 复盘归复盘。

任何 agent 超出本部门职责进行结论扩张，均视为越权。

### 2.4 结构化原则

所有输出必须进入模板化结构，不允许自由散文式分析直接进入决策层。

### 2.5 成长优先原则

系统不仅要提高当下研究质量，还要围绕用户的稳定性弱点进行训练。

重点关注：

- 机会比较能力
- 替代成本意识
- 情绪/时间压力下的遗漏项提醒
- 执行偏差纠正
- 重复性错误识别

## 3. 总体组织结构（修订版）

采用“太子 + 三省六部 + 早朝官 + 御史台 + 专项机构”的治理结构。

本系统分为三层：

### 3.1 治理层

治理层负责分拣、规划、审议、派发、汇总与节律管理，不直接承担主要业务研究执行。

组成如下：
- 太子：任务分拣与立项
- 中书省：规划与拆解
- 门下省：审议、封驳、返工
- 尚书省：派发、状态流转、回奏汇总
- 早朝官：日度、周度、重大事项会议节律

### 3.2 业务层

业务层负责投资相关的专业执行。

组成如下：
- 吏部：行为画像、成长训练、制度提醒
- 户部：仓位、组合、相关性、止损、账本
- 礼部：盘前、盘中、盘后流程，定时任务，配额治理，文书整编，简报与纪要
- 兵部：投资研究、预期差研判、机会排序、交易计划
- 刑部：执行监督、违规稽核、偏差归因、纪律问责
- 工部：数据、回测、技术统计、监控、自动化

### 3.3 专项机构层

用于承接六部难以优雅容纳、但长期有价值的职能。

组成如下：
- 皇城司：资讯中台、新闻与用户临时想法整理、议题入池
- 发改委：长期逻辑、行业景气、基本面跟踪、主题/行业榜单
- 国策库：延迟汇报、长期跟踪、报告嵌入的议题池（为机制，不一定是独立 agent）

### 3.4 外挂监察层

- 御史台：独立监督用户本人和系统整体质量，专查计划外行为、重复错误与机会遗弃问题。

### 3.5 组织原则

- 三省是治理骨架，六部是执行肌肉。
- 三省不替代六部执行，六部不越权代替三省治理。
- 门下省为必经节点，没有放行不得进入执行层。
- 尚书省是状态机与派发中枢，不是普通行政秘书。
- 早朝官不是装饰角色，而是维持制度节律的会议节点。
- 专项机构用于承接高频情报汇流、长期产业跟踪、延迟汇报议题等“六部不够优雅”但确有必要的功能。
- 门下省负责审议与加闸，不负责做部门间逐站消息中继；真正的流转编排权仍应留在尚书省。

## 4. 核心制度链（修订版）

本系统存在三条标准流转链：

### 4.1 标准即时任务链

用户
→ 太子（分拣与立项）
→ 中书省（规划书）
→ 门下省（审议 / 封驳 / 返工）
→ 尚书省（派发六部/专项机构）
→ 六部 / 专项机构执行
→ 尚书省（汇总回奏）
→ 早朝官（日度 / 周度 / 重大复盘会议）
→ 御史台（独立监察）

### 4.2 国策议题链（延迟汇报）

用户临时提出一个行业/逻辑/机会
→ 太子识别为“国策议题”而非即时答复任务
→ 皇城司整理成《议题卡》
→ 中书省规划其研究深度与未来挂载的报告类型
→ 门下省审议是否入国策库、是否缓议、是否只观察
→ 尚书省登记到国策库并派发发改委 / 工部 / 兵部进行异步跟踪
→ 礼部在指定的定期报告中自动纳入汇报
→ 兵部在机会排序中与其他候选统一比较
→ 早朝官在对应例会中集中呈报

### 4.3 定时任务链

礼部根据日程、优先级和配额预算
→ 通过 Cron / 定时调度触发任务
→ 尚书省按预定链路派发
→ 各部执行
→ 礼部整理定时报告、差异总结与历史对比
→ 早朝官纳入例会

### 4.4 关键节点铁律

#### 铁律 1：太子只做分拣，不做研究

太子负责：
- 判断是闲聊、研究、监控、计划、复盘还是问责类任务
- 提炼任务标题
- 创建任务卡
- 识别优先级与大类

太子不得：
- 直接规划任务细节
- 直接下研究结论
- 直接发往六部执行

#### 铁律 2：中书省只做规划，不做主要业务执行

中书省负责：
- 明确问题定义
- 拆解成子任务
- 指定需要哪些部门参与
- 指定证据需求与交付物标准
- 指定是否需要多轮会审或仅走短链路

中书省不得：
- 直接承担主要技术研究、基本面研究、回测、风控核算
- 用“自己先做一部分”替代制度派单

#### 铁律 3：门下省为必经审议层

任何正式任务要进入六部执行，必须经过门下省审议。

门下省有三种处理结果：
- 同意：允许进入尚书省派发
- 封驳：打回中书省重做
- 缓议：逻辑有道理，但时机/证据/替代成本不足，进入观察池或待补材料

没有门下省放行，不得进入正式执行层。

#### 铁律 4：尚书省掌控状态机与派发权

尚书省负责：
- 根据门下省审议结果向六部派发任务
- 维护任务状态
- 接收六部回奏
- 汇总形成统一结果
- 决定是否需要补充执行或二次会审

尚书省不得：
- 私自修改门下省审议结论
- 直接代替六部做专业判断

#### 铁律 5：六部只在授权范围内执行

六部负责各自专项工作，不得越权替代其他部门或三省。

#### 铁律 6：早朝官维持节律

早朝官负责：
- 盘前早朝
- 盘后小朝会
- 周度大朝会
- 重大失误复盘会

没有会议节律，系统容易退化为碎片化对话。

#### 铁律 7：礼部掌控定时节奏与配额纪律

礼部负责：
- 定时任务编排
- 重要报告的固定窗口保留
- 对 Coding Plan / 账户配额进行查询与调度建议
- 在配额吃紧时压缩次要讨论、保留关键报告

礼部可以建议“降级讨论深度、延后次要议题、暂停非关键会审”，但不得擅自删改已批准的重要任务。

#### 铁律 8：御史台独立监督，不受盈利结果免责

即使最终盈利，只要存在计划外违规，也可被御史台和刑部记录为纪律问题。

## 5. 治理层草案（修订版）

## 5.1 太子：任务分拣与立项官

### 核心使命

把用户的原始输入转成清晰的制度化任务，而不是直接解决任务。

### 职责

- 区分闲聊与正式任务
- 识别任务类型：
  - 研究类
  - 监控类
  - 计划类
  - 复盘类
  - 问责类
- 提炼任务标题
- 创建任务卡
- 判断任务是否需要进入完整三省六部流程，还是可以走短链路

### 输出模板

《立项分拣单》
- 任务标题：
- 任务类型：
- 用户原始意图：
- 建议处理路径：完整流程 / 短链路 / 仅记录 / 仅答复
- 优先级：
- 是否需要持续跟踪：是 / 否

---

## 5.2 中书省：规划中心

### 核心使命

中书省不负责主要研究执行，而负责把任务拆解成有边界、有证据要求、有交付标准的规划书。

### 职责

- 明确问题定义
- 拆成子任务
- 判断需要哪些部门参与
- 明确证据需求
- 明确交付物标准
- 判断是一次性任务、持续监控任务还是周期性任务

### 禁止事项

- 不直接做主要业务研究
- 不直接输出交易建议
- 不直接决定仓位
- 不绕过门下省把任务下发给六部

### 下设角色

#### 1）中书令·总规划官

职责：
- 统一规划视角
- 决定任务采用完整治理链还是简化链
- 保证规划不过度也不失焦

#### 2）中书舍人·任务拆解官

职责：
- 把任务拆成可执行子任务
- 指定交给哪些部门
- 指定先后顺序与依赖关系

#### 3）中书舍人·证据需求官

职责：
- 指定哪些问题必须用 A 级证据回答
- 指定哪些问题允许概率性判断
- 指定哪些问题当前证据不足不可下结论

#### 4）中书舍人·交付标准官

职责：
- 明确每个子任务的输出模板与质量门槛
- 防止执行层交出无法横向比较的散文式结论

### 输出模板

《投资旨意规划书》
- 任务目标：
- 任务类型：
- 需要回答的核心问题：
- 子任务列表：
- 指派部门建议：
- 证据要求：
- 输出模板要求：
- 是否需要会审：是 / 否
- 是否需要持续监控：是 / 否
- 计划时限：

---

## 5.3 门下省：审议与封驳中心

### 核心使命

门下省不是“提建议”，而是正式审议层。它负责挡住规划缺陷、证据缺口、时机错误和冲动切换。

### 职责

- 审查中书省规划书
- 审查重大换仓/切换申请
- 审查证据等级是否匹配任务重要性
- 审查是否存在过度研究、过度会审或链路过长问题
- 给出同意、封驳、缓议结论

### 下设角色

#### 1）给事中·规划审查官

职责：
- 检查规划是否清楚、是否过度或不足
- 检查子任务是否合理分派

#### 2）给事中·反证官

职责：
- 主动寻找反证与薄弱环节
- 防止支持性证据堆叠

#### 3）给事中·时机官

职责：
- 审查该任务是否需要现在做
- 检查当前是否只是逻辑正确但时机不对

#### 4）给事中·替代成本官

职责：
- 审核换仓、切换、放弃旧机会转做新机会的正当性
- 防止“狗熊掰棒子”式决策

### 审议结论

- 同意：进入尚书省派发
- 封驳：退回中书省重做
- 缓议：进入观察池、等待条件成熟或补充证据

### 制度说明

门下省是必经节点。没有门下省同意，正式投资任务不得进入执行层。

---

## 5.4 尚书省：派发、状态与回奏中心

### 核心使命

尚书省是任务状态机和派发中枢，不是单纯归档员。

### 职责

- 接收门下省结论
- 向六部派发任务
- 维护任务状态流转
- 接收六部回奏
- 汇总形成统一回奏
- 决定是否需要补充执行、二次审议、进入朝会

### 下设角色

#### 1）尚书令·总调度官

职责：
- 统筹派发顺序与优先级
- 控制流程长短，防止任务失控

#### 2）尚书左丞·状态官

职责：
- 维护任务状态，如：已立项 / 已规划 / 已封驳 / 已派发 / 执行中 / 待汇总 / 已回奏 / 已归档

#### 3）尚书左丞·归档官

职责：
- 记录规划、审议、执行、问责与复盘结果

#### 4）尚书右丞·回奏汇总官

职责：
- 汇总六部执行结果
- 整理为统一回奏
- 准备提交给用户和早朝官

---

## 5.5 早朝官：制度节律与会议节点

### 核心使命

维持系统的日度和周度节律，防止任务只在局部对话中碎片化漂移。

### 职责

- 盘前早朝：确认今日重点机会、风险点、执行计划
- 盘后小朝会：核对执行偏差、记录异常、形成简报
- 周度大朝会：总结本周最优决策、最差决策、重复性错误与遗弃机会
- 重大失误复盘会：针对严重偏差召开专项复盘
- 国策会：对国策库中的长期议题做阶段性汇报，而不是见一个议题答一个议题

### 输出模板

《朝会纪要》
- 会议类型：盘前 / 盘后 / 周度 / 专项复盘 / 国策会
- 主要议题：
- 今日/本周重点：
- 风险提醒：
- 执行偏差：
- 下阶段行动：

---

## 5.6 专项机构草案

## 5.6.1 皇城司：资讯中台与议题入池中心

### 核心使命

把用户零散想法、盘中突发信息、当日新闻流、历史跟踪事项整理成可流转的标准化议题，而不是让门下省亲自处理所有原始噪音。

### 职责

- 汇总当日新闻、公告、传导链、情绪热点
- 接收用户临时抛出的行业/机会想法
- 整理为《事件卡》或《议题卡》
- 判断应进入即时链路、观察池还是国策库候选
- 向中书省和门下省提供干净的输入材料

### 下设角色

#### 1）皇城司使·资讯总管

职责：
- 统一管理新闻流、消息流、用户临时想法流
- 去重、去噪、归类

#### 2）皇城司都知·议题整理官

职责：
- 把用户想法整理成《议题卡》
- 指明是立即研究、延迟汇报还是仅纳入观察

### 输出模板

《议题卡》
- 议题名称：
- 来源：用户提出 / 新闻 / 公告 / 长期跟踪
- 议题类型：行业 / 标的 / 宏观 / 主题 / 风险
- 用户原始逻辑：
- 当前已知事实：
- 待验证问题：
- 建议处理方式：即时 / 缓议 / 入国策库 / 放弃
- 推荐挂载报告：盘前 / 周报 / 月报 / 标的推荐 / 行业专题

## 5.6.2 发改委：长期逻辑与行业景气中心

### 核心使命

承担跨日、跨周、跨月的长期逻辑与行业景气跟踪，不把所有基本面长期任务都塞给兵部临时处理。

### 职责

- 跟踪长期产业逻辑、行业景气、供需演变、政策周期
- 维护行业/逻辑优先级榜单
- 为国策库提供持续更新
- 输出行业层面的排序，而不是直接替代个股交易计划

### 下设角色

#### 1）发改委主任·长期逻辑官

职责：
- 跟踪主题、行业、产业链的中长期逻辑
- 明确哪些属于短炒、哪些值得进国策库长期跟踪

#### 2）发改委副主任·行业景气官

职责：
- 输出行业景气与预期差榜单
- 标记景气上行、下行、拐点待确认、证据不足等状态

### 输出模板

《行业逻辑榜单》
- 行业/主题：
- 长期逻辑评级：
- 当前景气状态：
- 市场预期：
- 本系统判断：
- 验证信号：
- 风险点：
- 是否建议转交工部/兵部深挖：是 / 否

## 5.6.3 国策库：延迟汇报与长期跟踪机制

### 核心使命

把“不需要立刻答复，但值得研究并在未来某个固定场合汇报”的议题集中管理。

### 机制说明

## 8. 关键制度（修订版）

## 8.1 门下必经制度

任何正式投资任务，都必须经过门下省审议后，方可由尚书省派发至六部或专项机构。

## 8.2 国策入池制度

当用户提出一个不要求即时答复、但值得研究的行业/逻辑/机会时，太子应允许其进入“国策议题链”，而不是强迫系统当场给结论。

入池后必须明确：
- 是否进入国策库
- 应挂载到哪一类未来报告
- 责任部门是谁
- 下一次汇报窗口是什么

## 8.3 封驳返工制度

门下省对规划书和重大切换申请拥有正式封驳权。封驳后必须退回中书省重做，不得跳过。

## 8.4 状态机制度

任务状态至少包括：
- 已立项
- 已规划
- 已审议通过
- 已封驳
- 已缓议
- 已派发
- 执行中
- 待汇总
- 已回奏
- 已归档

## 8.5 换仓特别法

任何从 A 切换到 B 的操作，必须经过替代成本官审核。
最低必须回答：
- A 是否真的失效
- B 的优势是否显著
- 是否覆盖交易成本、等待成本、认知切换成本

## 8.6 观察池制度

新机会先进入观察池，不直接进入执行池。
只有在时机、证据、风格、替代成本都合理时，才升级为正式候选。

## 8.7 冷静期制度

以下情形强制进入冷静期：
- 计划外止损
- 临时追高
- 从原有持仓切换到新热点
- 大幅修改止损或仓位计划

冷静期内必须生成反方审查页。

## 8.8 证据等级制度

统一分级：
- A 级：原始数据、公告、行情事实
- B 级：统计研究、回测、高质量二手资料
- C 级：经验判断、逻辑推演、主观估计

## 8.9 越权稽核制度

## 8.10 定时任务优先级制度

礼部必须把固定的关键任务保留优先级，例如：
- 盘前早报
- 盘后复盘
- 周度大朝会
- 标的推荐报告
- 国策会

在配额紧张时，优先压缩：
- 次要闲聊式讨论
- 非关键多轮会审
- 低优先级探索任务

## 8.11 配额节流制度

若定时查询显示 Coding Plan / 账户剩余额度偏低，礼部配额官可提出以下节流方案：
- 将低优先级议题转入国策库延后汇报
- 缩短报告篇幅，只保留排序和关键变化
- 暂停低价值多 agent 交叉讨论
- 把深挖任务顺延到下个刷新窗口

但礼部不得擅自取消已批准的重要报告。

任何角色超出职责边界发言或代替其他部门作结论，均记为越权事件，由刑部记录。

## 9.1 推荐工作流（修订版）

### 研究/计划类任务

1. 太子立项分拣
2. 中书省形成《投资旨意规划书》
3. 门下省审议，给出同意/封驳/缓议
4. 尚书省向兵部、工部、户部、礼部及专项机构派发
5. 各部门执行并回奏
6. 尚书省汇总形成统一结果
7. 早朝官纳入盘前/盘后/周度会议
8. 御史台事后抽检用户行为与系统质量

### 国策议题任务

1. 用户随时抛出一个行业/逻辑/机会想法
2. 太子识别为“国策议题”
3. 皇城司整理《议题卡》
4. 中书省确定研究深度、责任部门、未来挂载报告
5. 门下省审议：入国策库 / 缓议 / 放弃
6. 尚书省登记并派发发改委、工部、兵部等持续跟踪
7. 礼部在未来的标的推荐报告、行业专题、周报或国策会中统一汇报
8. 兵部在机会排序表中把该议题对应候选与其他机会横向比较

### 盘中执行类任务

1. 礼部盘中官和工部监控官只盯计划内触发条件
2. 若用户想切换、追高、计划外止损，进入门下省替代成本/冷静期流程
3. 刑部记录是否违规
4. 御史台对严重偏差发起监察

### 定时任务

1. 礼部时程官维护任务日历
2. 礼部配额官定时查询配额状态
3. 若配额健康，则按正常节奏触发盘前、盘后、周报、国策会等任务
4. 若配额吃紧，则按优先级制度压缩次要任务
5. 执行结束后，礼部差异对比官输出与上次相比的变化摘要

### 复盘类任务

1. 礼部盘后官整理当日事实
2. 刑部区分决策问题与执行问题
3. 吏部更新行为画像
4. 机会遗弃御史检查被放弃机会后续表现
5. 周度大朝官组织总结

### 复杂跨部门流水线（推荐写法）

用户提出行业/主题想法或当日新闻触发一个复杂议题时，推荐链路如下：

用户输入 / 当日新闻
→ 皇城司整理
→ 中书省规划
→ 门下省审议
→ 尚书省派发给发改委（长期逻辑/行业榜单）
→ 尚书省再派发给工部（标的数据、技术统计、回测）
→ 尚书省再派发给兵部（交易含义、机会排序、计划草案）
→ 户部 / 刑部 / 吏部给出风险、执行、行为侧反向意见
→ 门下省做二次审议
→ 尚书省汇总
→ 礼部写入定期报告或朝会汇报

制度说明：
- 门下省负责审议与加闸，不做逐站传话员
- 尚书省负责跨部门流水线编排
- 这样既保留制衡，也保留复杂协作能力

## 15. 与原始 Edict 架构的对比与修正说明

这一节用于回答一个关键问题：当前投资版草案是否相对原始项目弱化了“制衡”和“规划”？

结论：

- 是，上一版草案在“业务角色”上写得更丰满，但在“制度骨架”上写得偏弱。
- 主要问题不是六部写错，而是把部分本该属于三省治理层的职能，写成了业务研究层；同时把部分本该属于六部执行层的内容，提前塞进了中书省。
- 因此，必须做一次结构回摆：恢复原始项目的治理链条，再把投资业务角色挂载到正确的层级上。

### 15.1 原始项目的真正骨架

原始 Edict 的核心不是“很多官员”，而是下面这条制度链：

用户 / 皇上
→ 太子（分拣）
→ 中书省（规划）
→ 门下省（审议 / 封驳）
→ 尚书省（派发 / 调度 / 汇总）
→ 六部与早朝官（执行 / 文书 /复核 / 日常节律）
→ 回奏 / 归档

这条链条的精华在于：

1. 规划与执行分离
2. 审议是强制节点，不是装饰
3. 派发与汇总独立成层，不与研究混合
4. 六部负责专项执行，而不是替代三省治理

### 15.2 上一版草案偏弱的地方

上一版最主要的偏差有四个：

#### 偏差 1：把中书省写成了业务研究中心

上一版把“新闻情报官、技术统计官、基本面预期差官”都放进中书省。

这会导致：
- 中书省不再是“先规划、后派工”，而变成“自己先做一大半”
- 规划环节变薄，任务拆解与研究执行混在一起
- 门下省审的就不再是“规划案”，而更像“研究稿”

这削弱了原始 Edict 中最关键的“先规划，再执行”的制度价值。

#### 偏差 2：门下省虽然还在，但少了“必经 + 可打回 + 强制返工”的压迫感

上一版写了封驳和缓议，但还不够突出“没有门下省放行，任何交易案不得进入执行层”这条铁律。

也就是说，门下省写了职责，但“制度牙齿”不够显性。

#### 偏差 3：尚书省被写得偏行政，没写足“状态机中枢”

原始项目中，尚书省不是普通文员，而是任务状态流转和部门调度的中枢。

上一版虽然提到了调度和归档，但没有把尚书省写成：
- 任务状态守门员
- 六部派发中枢
- 回奏汇总中心
- 节点阻塞处理者

#### 偏差 4：六部与三省的边界有些混

比如：
- 技术统计更像工部执行能力，而不是中书省能力
- 基本面机会评估更像兵部执行能力，而不是中书省能力
- 新闻整理更接近礼部/兵部的执行输入，而不是中书省本体

换句话说，上一版“角色挺聪明”，但“官制不够正”。

### 15.3 正确的修正方向

正确做法不是推翻上一版，而是把它分成两层：

#### 第一层：治理层（必须保留原始 Edict 骨架）

- 太子：只负责分拣、建任务、清洗用户原始意图
- 中书省：只负责规划，不直接做主要研究内容
- 门下省：只负责审议、封驳、强制返工
- 尚书省：只负责派发、状态流转、汇总、归档

这层决定“制度是否还像原项目”。

#### 第二层：业务层（投资专用）

- 吏部：行为画像、成长训练
- 户部：仓位、相关性、止损、组合风险
- 礼部：盘前、盘中、盘后制度化节律，会议纪要与文书
- 兵部：投资逻辑、机会排序、交易计划、基本面预期差研判
- 刑部：执行监督、违规记录、问责归因
- 工部：数据、回测、技术统计、监控、自动化
- 早朝官：每日晨会、周会、重大复盘召集
- 御史台：独立监察（新增机构）

### 15.4 修正后的映射关系

下面给出“原项目角色 → 投资版建议映射”。

#### 太子

原项目：消息分拣，区分闲聊与任务，提炼标题并建任务。  
投资版：保持不变。只增加一个能力——识别任务类型：研究 / 监控 / 计划 / 复盘 / 执行偏差。

#### 中书省

原项目：规划中心，负责把任务拆成若干子任务，并指明交给哪些部门。  
投资版：恢复这一定位，不再让中书省直接承载主要研究执行。

建议下设：
- 中书令·总规划官
- 中书舍人·任务拆解官
- 中书舍人·证据需求官
- 中书舍人·交付标准官

中书省输出的不是研究报告，而是《投资旨意规划书》。

#### 门下省

原项目：审议中书省规划，必要时封驳，强制返工。  
投资版：不仅保留，还要更强。

建议下设：
- 给事中·规划审查官
- 给事中·反证官
- 给事中·时机官
- 给事中·替代成本官

门下省审的第一对象是“规划书”，不是直接审所有原始研究细节。
在交易换仓场景下，也可审“切换申请”。

#### 尚书省

原项目：派发六部、维护状态流转、汇总成果、形成回奏。  
投资版：恢复为状态机与派单中枢。

建议下设：
- 尚书令·总调度官
- 尚书左丞·状态官
- 尚书左丞·归档官
- 尚书右丞·回奏汇总官

#### 户部

原项目：偏数据、量化、账目、资源类执行。  
投资版：组合风险、仓位、相关性、止损与账本。

#### 礼部

原项目：偏文书、格式、报告、对外呈现。  
投资版：盘前/盘中/盘后流程、会议纪要、日报周报、信息整编。

#### 兵部

原项目：偏竞品、策略、战术分析。  
投资版：投资逻辑、标的筛选、基本面预期差、机会排序、交易计划。

#### 刑部

原项目：偏质检、纠错、风险审查。  
投资版：执行监督、违规稽核、偏差归因、纪律问责。

#### 工部

原项目：偏技术、搭建、数据处理。  
投资版：回测、技术统计、监控自动化、脚本工具、数据基础设施。

#### 吏部

原项目：偏人事、官员管理。  
投资版：用户行为画像、成长训练、错误标签、制度提醒。

#### 早朝官

原项目：节律性汇总和朝会感。  
投资版：必须恢复其地位，负责：
- 每日盘前早朝
- 盘后小朝会
- 周末大朝会
- 重大失误复盘会

上一版对它写得太轻，这里要补回来。

#### 御史台（新增）

原项目：公开版本中不是主骨架核心之一。  
投资版：新增独立监察机构，用来盯用户本人和系统整体质量。

### 15.5 修正后的真正制度链

修正后，投资版应该是这条链：

用户
→ 太子（分拣）
→ 中书省（规划）
→ 门下省（审议 / 封驳）
→ 尚书省（派发）
→ 六部执行（兵/工/户/礼/刑/吏）
→ 尚书省（汇总回奏）
→ 早朝官（日度/周度会议复盘）
→ 御史台（独立监察）

这才是真正“保留原项目治理力”的投资版。

### 15.6 最关键的修正结论

所以，用户的担心是正确的：

- 上一版强化了专业角色
- 但确实弱化了“原项目式的规划链与制衡链”

正确修正不是删掉新角色，而是：

1. 把中书省从“研究执行层”改回“规划层”
2. 把门下省写成真正的必经审议层
3. 把尚书省写成状态机和派发中枢
4. 把业务角色下沉到六部
5. 把早朝官恢复为节律性总结与会议系统
6. 保留御史台作为用户成长监察外挂

### 15.7 修订建议

基于这一判断，下一版文档建议做如下修订：

- 把“新闻情报官、技术统计官、基本面预期差官”从中书省迁出
- 将其分别重挂到礼部 / 工部 / 兵部
- 为中书省新增“总规划官、任务拆解官、证据需求官、交付标准官”
- 为尚书省新增“状态官、回奏汇总官”
- 为早朝官单列职责说明
- 把门下省的“必经审议、封驳、返工循环”写成制度铁律

一句话说透：

上一版更像“投资部门图”，还不够像“投资版三省六部制度图”。
下一版要把这两者重新接起来。

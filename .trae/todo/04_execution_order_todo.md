# 投资版 Edict / OpenClaw 执行顺序清单（TODO）

本清单不是按机构罗列，而是按“真正的开发依赖顺序”排列。

目标：避免出现“概念设计很完整，但最基础的治理链还没跑通”的情况。

使用方式：
- 从上到下执行。
- 每完成一个阶段，都先做验收，不要直接跳到后面的花活。
- 任何阶段如果发现前一阶段的职责边界不清楚，优先回修 SOUL.md 和模板，不要急着加功能。

---

## 总体顺序图

```text
A. 冻结制度边界
→ B. 跑通治理骨架（MVP）
→ C. 固化输出模板
→ D. 跑通盘前/盘后/复盘短链路
→ E. 引入专项机构（皇城司 / 发改委 / 国策库）
→ F. 跑通复杂议题流水线
→ G. 引入定时任务与配额治理
→ H. 自动化、统计研究、体验优化
```

### F2. 跑通标准复杂链
- [ ] 用户想法 / 当日新闻 → 皇城司整理
- [ ] 皇城司 → 中书省规划
- [ ] 中书省 → 门下省审议

- [ ] 尚书省 → 户部 / 刑部 / 吏部（风险 / 纪律 / 行为反向意见）
- [ ] 门下省二次审议
- [ ] 尚书省汇总
- [ ] 礼部写入定期报告 / 早朝汇报

### F3. 跑一个真实案例
- [ ] 选一个行业，例如造纸、券商、AI 算力或你当前最关心的板块

## 一句话执行原则

先把朝廷的门、路、印、驿站修好，再谈边军、密探、粮仓和钟鼓楼。

翻成工程话就是：
**先路由，后模板；先闭环，后扩展；先能用，后好用。**
